# ratchet (spec docs/features/active/answers-that-hold-2026-08/specs/

# into the gate's own scripts/lib/ budget file, keyed by change id").
#
# A release-notes change whose action.scope is "local" or "space" must
# carry a detect: — the ONLY way `a2a adapt --done` can ever verify a
# recorded obligation rather than trust an agent's word (spec 13
# §"THE MEASUREMENT" finding 3) — or a row in this file naming it as
# exempt. scripts/check-release-note-detect.sh reads this file; it does no
# YAML parsing of its own (internal/notes/detectcheck.go does that, `go
# run` from the gate — D-7).
#
# THE FROZEN CEILING IS NOT THE SPEC'S "40 of 44". That figure was the P13
# spec's own (0.19.0, 0.25.6] MEASUREMENT window illustration — 44 changes
# obliged the reader in that one range, 40 of which carried no detect:.
# Scoping THIS GATE to that same hardcoded window would make "forward-only"
# mean "forward of one arbitrary old tag" forever, and a 40-entry budget
# checked against a wider scan reds on arrival — the gate and the ratchet
# must describe the SAME population. So this gate scans the WHOLE embedded
# release-notes corpus (every releasenotes/*.yaml), and the real count of
# scope:local|space changes with no detect: across that whole corpus, on
# 2026-08-28, is 92 — every id below, one per line, no comment needed per
# row (the reason is uniform: "authored before this gate existed").
#
# AC-14: this number is a printed number that may only shrink. Retrofitting
# a detect: to any change below and deleting its row here is an ORDINARY
# commit; the ceiling below moves down in the SAME commit, never up. A row
# that no longer describes a real violation (a detect: was added, the
# change no longer exists) must be deleted or the gate reds naming it as
# stale — the ratchet drains, it does not merely cap.
#
# Format: one change id per line. "#" starts a comment; blank lines are
# ignored. A NEW release-notes change with scope: local|space and no
# detect: that is not listed here REDS the gate, by id.
#
