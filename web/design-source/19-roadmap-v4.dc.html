Next proposal — autonomous verified delivery loop

Two physically separate systems alternate short-lived local agent sessions without a human invoking each command, and hold a claim across machines long enough to finish a turn. The private delivery-and-verdict loop those sessions would drive already ships — see Shipped now.

What is actually decided
The delivery-and-verdict half is shipped and released; running it unattended is documented for exploration, not approved for implementation.
The public Git space remains the control plane.
Private runtime payloads must not be committed there.
What is not promised

No watcher, cross-machine claim, second transport driver or agent-runtime adapter is a shipped promise. If you can name one of these, it does not exist yet.

Commercial direction, stated once

A hosted, cross-machine version of this loop — one that runs unattended without a human invoking each local command — is a likely candidate for the first Pro capability. Packaging, limits, pricing and release timing are undecided.

There is nothing to buy, reserve or register interest in. This paragraph is a product direction, not an offer — and it is the only commercial sentence on this site.

Two things that are not the same

The architecture plan describes a single-operator Go Hub that mirrors and indexes spaces and serves read APIs and notifications. It explicitly does not transport runtime payloads and does not orchestrate agents.

That is a different thing from a future multi-tenant product surface. Neither one is available today, and neither is presented as protection or capability you have now.
